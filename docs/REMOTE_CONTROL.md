# 手机通过服务器控制 Windows / Linux 电脑：v0.3.1 远程任务代理

> **状态：基础链路已实现，但不是原生桌面应用，也不是任意 GUI 自动化工具。** 本页所有命令要求用户自己在受控设备执行。远程服务还未通过公网攻击面审计，不建议未经额外防护直接暴露。

## 拓扑

```text
Android 手机（Web/PWA，未来 APK）     Windows / Linux 桌面（Web/PWA，未来 .exe/AppImage）
                |                                   |
                |  HTTPS（用户访问聊天、发任务）      | HTTPS 主动轮询（设备令牌）
                v                                   v
                  云服务器 FastAPI + SQLite
                 ├─聊天 / 智能体 / 群聊（统一存储）
                 ├─设备清单、令牌哈希、心跳
                 ├─远程任务队列 / 执行结果
                 └─可选反向代理 HTTPS / VPN

桌面端 agent-team-worker 在已授权的本地工作目录执行白名单任务，
执行结果回传服务器，手机刷新便能看到。电脑不需要公网 IP，服务器不运行电脑 GUI。
```

## 服务器

1. 将项目部署到有 HTTPS 的可信服务器（建议 TLS 反向代理、VPN，禁止把裸 HTTP 暴露公网）。**必须**设置足够随机的 `AGENT_TEAM_ACCESS_TOKEN`，否则全部远程设备管理 API 都拒绝访问；此口令和设备令牌必须不同。
2. 在服务器上启动 `agent-team-server --host 127.0.0.1 --port 8765`，使用反向代理的 TLS 将远端请求转发到该地址。若通过受保护的 VPN 访问，也可使用私网监听，但不应使用明文 HTTP 穿越公网。
3. 手机访问 `https://你的服务器域名/remote.html`，输入所有者口令，在设备页面创建一台电脑并复制生成的**一次性设备令牌**。
4. 所有聊天记录由这一台服务端的 SQLite 集中存储，桌面/手机访问同一地址即可同步；已打开的聊天页每 8 秒检查一次新消息（可见页面时）。跨设备冲突合并、端到端加密尚未完成。

## Windows / Linux 电脑

1. 安装同一仓库：`python -m pip install -e .`。
2. 给电脑准备一个专门的**授权工作目录**，例如 `D:\\AgentTeamWorkspace` 或 `~/AgentTeamWorkspace`。不要直接设为整个家目录、系统根目录或存放密钥的目录。
3. 在受控电脑的终端设置两个环境变量：

   - `AGENT_TEAM_HUB_URL=https://你的服务器域名`
   - `AGENT_TEAM_DEVICE_TOKEN=手机设备页面生成的一次性令牌`

4. 启动 `agent-team-worker --workspace ~/AgentTeamWorkspace`（Windows 请换成对应路径）。如需手机下发便签到电脑文件夹，添加 `--allow-write` 参数。
5. 电脑会每隔 4 秒从服务器领取一次任务；完成后回传成功/失败和简短结果。电脑退出进程后会显示离线，尚未提供后台服务安装或图形化托盘。

**注意：** 运行时不要把含设备令牌的完整命令复制到群聊、日志、脚本仓库或公开截图中。设备令牌被泄漏时，立即从设备页撤销并重新配对。

## v0.3 已允许的动作

| 动作 | 实际行为 | 限制 |
| --- | --- | --- |
| `system_info` | 返回操作系统和 Python 版本 | 不含 Shell 命令 |
| `notify` | 在电脑任务接收终端显示通知文字 | 不会自动执行通知里的指令 |
| `read_text` | 从授权目录读取 12KB 内的 UTF-8 文本（限定后缀） | 禁止隐藏路径、符号链接或越界，不支持二进制/大文件 |
| `list_files` | 列出指定工作目录的文件/文件夹名称 | 不允许越界、隐藏路径或通过符号链接穿越；最多 80 项 |
| `write_note` | 将文本保存为工作目录 `AgentTeamInbox/note-*.txt` | 必须显式 `--allow-write`，限制 8 千字 |

**未实现：** 任意程序启动、鼠标键盘控制、文件上传/下载、远程 Shell、屏幕观看、智能体自主执行计划、自动化授权审批、任务断线恢复和原生应用安装包。

## 安全边界

- 一台电脑只拿到本机 **设备令牌**，不能访问用户模型 Key、其他设备任务或全部聊天记录。用户所有者口令仅用于手机/桌面 Web 管理。
- 服务器只保存设备令牌 SHA-256 摘要；原文只在创建设备时显示一次。撤销设备会取消排队中的任务，进行中的任务不能保证立刻中止。
- 所有动作有白名单。不要添加 `shell`、`eval`、不受限的文件写入，也不要给任意三方 Skill 自动打开本机执行权限。
- 文件操作只允许用户**显式指定**的根目录。符号链接、目录联接点和隐藏路径会被拒绝；文本读取限制 12KB 和常用纯文本后缀。文件系统隔离不等于操作系统沙箱；真正高权限插件需要单独的授权与审计方案。
- v0.3 是单人试验系统。部署公网前仍需要完善设备配对确认、服务端限速、用户登录、TLS 管理、审计、任务恢复、系统凭据存储及安全测试。

## v0.3.1 任务生命周期与故障恢复

- 任务状态：`queued`（待领取）→ `running`（执行中）→ `completed`/`failed`（完成/失败）。
- 所有者可取消**尚未被领取**的任务；在运行中的任务不支持中途取消，以防误以为已停止。
- 正在运行的任务超过 180 秒未完成，标记为 `interrupted`（中断）；**不会自动重试**，因为远程电脑可能已经产生了副作用（如写入便签），只是未能上报。
- 所有者可从任务界面手动重新安排 `failed`、`cancelled`、`interrupted` 的任务，新任务 ID 与原任务关联；对中断的任务重试前要人工核对电脑结果。
- 手机任务页支持状态筛选、进度显示、取消与手动重试。
- 当前 180 秒超时是基础版本固定值；耗时较长的工具执行和心跳续租需要后续扩展。
- 任务队列在 SQLite 中持久化，但设备端尚没有严格的幂等执行保证；不要把本版本视为事务性远程自动化平台。

## v0.3.2 小迭代：文本读取与路径隔离

- 增加 `read_text`：手机可请求读取**事先授权工作目录内**的 UTF-8 `.txt`、`.md`、`.csv`、`.json`、`.py`、`.log`、`.yaml`、`.yml`、`.toml` 文件，限制 12KB。
- 修复通过工作目录内符号链接指向隐藏文件的路径绕过风险；目录联接点也会拒绝。
- 不意味着可以远程访问整台电脑的文件。请勿把密码、令牌、个人隐私文件放进授权目录。
